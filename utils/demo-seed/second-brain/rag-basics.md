# 检索增强生成（RAG）的工作流程

本文说明一个最小可用的 RAG 系统由哪些环节组成，以及每个环节负责解决什么问题。
（演示文档：内容为自撰技术说明，用于演示知识库检索与问答流程。）

## 一、为什么需要检索增强

语言模型的知识来自训练语料，它无法知道你的私有资料。如果直接把问题丢给模型，
模型只能凭参数里的记忆作答，遇到私有内容时容易编造看似合理但没有依据的答案。

检索增强生成（Retrieval-Augmented Generation，RAG）的思路是：先在你的资料里
找出与问题相关的片段，再把这些片段作为上下文交给模型，让它基于给定材料回答。

## 二、四个核心环节

### 1. 解析

把上传的文件转换成纯文本。不同格式需要不同的解析器：PDF 要处理分栏与页眉页脚，
Word 要保留标题层级，Markdown 要保留段落边界。解析质量直接决定后续环节的上限，
如果这一步丢掉了标题和编号，切片就会切断语义。

### 2. 切片

把长文本切成适中长度的片段。片段太短会丢失上下文，太长会稀释相关性，
并挤占模型可用的上下文窗口。常见做法是按段落或标题切分，并让相邻片段保留少量重叠，
避免一句话被从中间截断。

### 3. 向量化与检索

用嵌入模型把每个片段转换成一个高维向量，语义相近的文本在向量空间中距离更近。
提问时把问题也转成向量，然后按余弦相似度找出最接近的若干个片段。

这一环节的关键取舍是"召回多少"：召回太少可能漏掉关键信息，
召回太多会引入噪声并增加模型负担。

### 4. 生成

把检索到的片段和用户问题一起组成提示词交给模型，并要求模型只依据给定材料回答。
回答时标注来源片段，让使用者可以回溯核对，这也是判断答案可信度的主要依据。

## 三、常见的失效点

- **解析失败**：扫描件没有文字层，需要额外做 OCR。
- **切片切断语义**：表格或代码块被从中间切开，检索到的片段无法独立理解。
- **检索跑偏**：提问用词与文档用词差异过大，向量相似度无法匹配。
- **上下文过载**：召回片段过多，模型注意力被稀释，反而答得更差。
- **无依据作答**：模型忽略了给定材料，仍然依赖自身记忆回答。

## 四、边界说明

RAG 降低幻觉，但不消除幻觉。系统的可信度取决于三件事：资料本身的质量、
解析与检索的准确度，以及是否要求模型标注来源。把"回答有引用"作为默认要求，
比单纯追求回答流畅更有价值。
