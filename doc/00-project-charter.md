# 个人工程作品集平台：项目章程

## 1. 项目定位

这是一个面向招聘方、技术面试官和潜在合作方的个人工程作品集平台。它通过结构化项目案例、个人贡献、技术决策、验证证据和精选学习摘要，展示用户的软件开发与 AI 应用开发能力。

## 2. 核心叙事

不是简单回答“我会什么”，而是回答：

1. 我解决过什么问题？
2. 我承担了什么职责？
3. 我为什么这样设计？
4. 我如何验证结果真实可靠？
5. 我如何把知识从 Java 迁移到 Python，并形成复利？

## 3. 首期成果

首期至少展示三个项目：

1. 参与合作的 Java 项目：诚实展示团队成果与个人贡献边界。
2. 独立开发的 Java RAG 知识库项目：展示第一个独立全栈项目。
3. AI Translator：展示 Python/FastAPI、翻译学习闭环和生产级工程实践。

## 4. 项目边界

### 本项目负责

- 项目展厅和项目详情。
- 技术栈、架构、决策和验证证据。
- 项目版本、源码、Demo 和运行说明。
- 精选学习摘要。
- 可追溯的知识网络。
- 管理、审核、发布和回滚。

### 本项目不负责

- 在线代码执行。
- Skill 测试和实验运行。
- 未完成项目的临时调试。
- 通用博客、社区、课程或多用户协作。
- 实验平台的任务队列、沙箱和运行资源。

## 5. 关联空间

```text
ai-dev-lab
  学习、实验记录和详细复盘
       ↓ 精选摘要
personal-portfolio
  审查后稳定展示
       ↑ 发布快照
未来 dev-playground
  未完成项目、Bug、Skill 和技术栈实验
```

## 6. 成功标准

- 三个项目均经过版本、隐私、授权和运行审查。
- 每个项目都有问题背景、个人贡献、技术栈、架构、决策、证据和运行入口。
- 公开区不暴露草稿、密钥、真实用户数据或内部信息。
- 发布使用不可变版本，可追溯、可回滚。
- 作品集核心功能不依赖实验平台。
- 原型、测试、浏览器验证和发布人工确认全部完成。

## 7. 不做的妥协

- 不因追求速度跳过项目审查。
- 不把“能打开页面”当作完整交付。
- 不把合作成果包装成个人独立成果。
- 不把未验证的版本、性能数字或技术能力写成事实。
