## 阶段 0：门禁

**目标**：不崩靠机制，不靠记性。现在能崩的原因是"所有检查都靠手动记得去跑"。

- [x] **0.1 统一门禁命令** `node utils/verify.mjs`
      秘密扫描 → 构建 → 浏览器验收 → 后端测试，一个命令一个退出码。
      已双向验证：注入假凭据会被拦下，清理后恢复通过。
- [x] **0.2 git 钩子**：未通过 verify 的改动推不出去
      装在 pre-push（不是 pre-commit）：提交是廉价本地动作，推送才会把问题带给别人。
      范围自动判定：触及 `project/backend/` 才跑后端测试。
      两条路径均已真实验证：前端路径与后端路径各跑过一次真实推送，均通过。
      期间修掉一个真实缺陷——钩子环境里 `mvn` 找不到（本机 PATH 有畸形条目，
      落单引号使 cmd.exe 的搜索失效），改为按绝对路径调用 Maven 后解决。
- [x] **0.3 运行手册** `doc/24-runbook.md`
      把启动命令从 `self-reflection-lite.md`（个人反思文件）里搬出来。团队不会翻别人的个人反思。
      含快速开始、日常循环、命令清单、环境变量、部署现状、故障对照表。
- [x] **0.4 部署自动化**：推送即自动部署
      Netlify 站点已关联 GitHub 仓库 `Sunshine-mai/personal-portfolio`，监听 `main`。
      构建配置由 `netlify.toml` 提供；`project/frontend` 为 base，`dist` 为发布目录。
      **必须注意**：Netlify 不支持 Gitee，只支持 GitHub / GitLab / Bitbucket / Azure DevOps，
      所以触发部署要推 `github` 远端——只推 Gitee 不会部署（已写入 RUNBOOK）。
      制品写入 `<meta name="build-commit">`，线上因此能自证是哪个提交构建的。
      实测确认：线上 HTML 的标识、本地 HEAD、Netlify 面板显示的 `main@<sha>` 三者一致。

**完成标志**：改一行文案 → 跑一个命令 → 自动上线。中间不需要记住任何参数，且故意写坏的改动推不上去。

## 阶段 1：首页技术网络图

**目标**：把"用过什么技术"变成可扫读的图，而不是文字列表。

- [x] **1.1 设计稿** `doc/26-tech-graph-design.md`
      数据模型、布局、交互、可访问性、验收断言、明确不做全部先定下来。
      **设计过程中修正了一个自己的错误模型**：原本打算用"技术共现"（两个技术同现于一个项目就连线），
      算完边数才发现那是给每个项目生成一个完全图，5 个项目叠加后密度约 29%，必然变成毛线球。
      改为**二部图（项目↔技术）**，密度约 5%，且每条边都是可直接核验的事实而不是推断。
- [ ] **1.2 实现**：SVG + 真实 DOM 节点、固定种子的确定性布局、鼠标邻近高亮、尊重 `prefers-reduced-motion`
- [ ] **1.3 测试**：新增验收断言（项目/技术/边数量、坐标在界内、无持续动画、高亮可锁定与清除、键盘可达、文字版与图等价）
- [ ] **1.4 上线**

**⚠ 实施前的前置依赖（1.1 暴露出来的）**：图的数据从各案例的 `stack` 派生，而目前只有
LexiFlow 与 Folio 两个案例有 `stack`。知衡的台账已过期、练习区没有台账条目。
**只有 2 个项目的图会让跨项目复用几乎不可见——那不是中性结果，而是失真（显得比实际弱）。**
因此顺序调整为：**先做阶段 2 的 2.1／2.2 补数据，再回来做 1.2。**

**完成标志**：首页出现网络图；已有验收全过 + 新增断言全过；**只用键盘也能浏览**；关闭动画偏好时静态可读。

**技术选型已定（不需再讨论）**：SVG + DOM，不用 canvas；布局用固定种子的确定性迭代，不做实时力导向物理；不引入第三方依赖。
理由：物理图每次位置都不同，验收断言不了；canvas 对屏幕阅读器不可见。

## 明确不做（防止范围膨胀）

这一节和上面的清单同等重要。**每次想加东西之前先看这里。**

- **不做完后端**：它已按"未接入、冻结"处理。前端没有任何界面调用管理端，做完也不会改变访客看到的内容。要在线编辑内容应作为独立需求重新立项。
- **不做技术栈树状图**：5 个案例层级高度相似，树会重复成噪声。更复杂的知识图谱式展示留给独立立项的知识体系项目。
- **不在作品集里跑实验代码**：ADR-001/002。实验、Skill 测试、未完成项目另立项目。
- **不给截图上色或改字**：截图是证据，只允许派生（裁剪、缩放），不允许修饰。为好看而改图等于伪造证据。
- **不引入指标数字**：只展示能追到证据的数字（迁移次数、测试数、验收项数）。想不出处就不写。
- **不为"看起来专业"而加流程**：每一项门禁都要能说出它拦住过什么，或将来会拦住什么。
