# 测试与验收方案

## 1. 测试层级

```text
静态检查/内容规则
→ 单元测试
→ API 与数据库集成测试
→ 浏览器端到端测试
→ 安全/依赖/秘密扫描
→ 候选部署冒烟
→ 生产发布后验证
```

## 2. 核心单元测试

- 发布状态机所有分支。
- 项目字段和 URL 校验。
- 贡献边界规则。
- 知识节点和边约束。
- 发布门禁聚合。
- 权限判断和敏感字段过滤。
- Markdown/富文本净化。
- 版本冲突和幂等发布。

## 3. API 与数据库测试

- 公开接口不返回草稿、私有字段或内部路径。
- 管理 API 鉴权、越权和会话过期有效。
- 发布前门禁失败时禁止发布。
- 已发布内容编辑后旧版本继续公开。
- 并发编辑返回冲突而不是静默覆盖。
- 数据库可从零迁移、升级、备份和恢复。
- 事务失败不留下半发布数据。

## 4. 浏览器测试

公开路径：首页→项目列表→项目详情→架构/决策/证据→外链。

管理路径：登录→创建修订→提交审核→批准/驳回→发布→撤回/回滚。

必须验证 PC、平板、手机、键盘操作、加载、空状态、错误状态、断网和重复点击。

## 5. 旧项目验收

每个旧项目必须完成版本锁定、秘密扫描、许可证检查、干净环境运行、核心功能验证、Demo 核验、贡献边界确认和人工批准。

## 6. 发布阻断项

- 敏感信息命中。
- 未授权内容。
- 项目版本不一致。
- 权限绕过。
- 草稿泄露。
- 迁移或备份恢复失败。
- 核心浏览器路径失败。
- 构建产物与批准版本不一致。

## 7. 验收证据

保存测试报告、覆盖率、接口报告、浏览器截图、扫描报告、依赖清单、SBOM、版本 SHA、部署日志、备份恢复记录、回滚演练和人工批准记录。
