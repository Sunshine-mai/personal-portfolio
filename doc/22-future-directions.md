## 方向一：知识架构体系（网状知识图谱）

### 想法

把个人的知识组织成一张**可以互相链接的网**，而不是一棵分类树：

- 以节点呈现，节点之间可以网状互链，整体是"会动"的形态
- 分几个大类，目前想到的：
  - **软件开发体系**：操作系统、前端、后端、MySQL 等技术栈（具体清单待补）
  - **学习知识体系**
  - **英语单词场景体系**
- 内容由站点所有者和协作者一起逐步列出并归纳

### 与现有设计的关系

这个方向**在项目立项时就已经规划过**，不是新想法：

| 已有基础 | 位置 |
|---|---|
| 知识节点表 `knowledge_nodes`（id / label / category / description） | `project/backend/src/main/resources/db/migration/V3__create_public_content_tables.sql` |
| 知识图谱接口 `GET /api/public/knowledge/graph` | `PublicContentController` |
| 响应结构 `KnowledgeGraphResponse` | `project/backend/src/main/java/com/crow5/portfolio/dto/` |
| 节点与边的数据模型、约束 | `doc/05-data-model.md`、`doc/02-information-architecture.md` |
| V2 蓝图中的 `KnowledgeEdge` 实体 | `doc/15-portfolio-v2-product-and-engineering-blueprint.md` |

**缺口**：边的表与实体尚未建；图谱接口目前把边硬编码为空列表，是个空壳；
公开知识节点接口还没有按 `published` 过滤，见 `doc/STATUS.md` 的已知缺陷。

### 待确认

- 节点分类的最终口径（目前是三个大类，是否够用）
- 边是否需要有类型与方向（"前置知识"、"相关"、"同属"等）
- 内容来源与维护成本：手工录入，还是从既有笔记批量导入

## 方向二：可复用的技术栈试用与测试平台

### 想法

一个**把技术栈"拖进来就能跑"**的基础框架：

- 提供统一的基础骨架，底层实现方式与协作者共同商议
- 目标是**快速、可重复利用**的试用环境，而不是一次性脚本
- 被测试的对象不限：编程语言（Java、Python，以及尚未接触过的）、
  团队协作工具与流程、数据库等
- 用于随时试用新发现的技术栈，或验证别人的方案

### ⚠️ 项目边界：必须独立立项

这一项**不能并入作品集**。`CLAUDE.md` 与 `doc/00` 的章程已经写明：

> 本项目只负责稳定的成果展示、内容审核与发布。
> **不执行任意项目代码，不承载 Skill 测试或实验运行。**
> 测试/实验平台属于未来独立项目，**不与本平台共享运行时、数据库或部署进程**。

这个想法正是章程预留的"未来独立测试平台"，因此：

- 需要**新建独立仓库**，独立运行时、独立数据库、独立部署
- 作品集里只呈现它的**结果与证据**，不承载它的执行
- 若要展示，按合作项目/独立项目的既有方式，作为案例接入

### 待商议

- 底层用什么：容器编排、进程隔离，还是语言运行时沙箱
- "拖进来"的输入形态：压缩包、仓库地址，还是配置文件
- 安全边界：能跑什么、不能跑什么，资源与时限如何限制
- 与作品集的展示接口：只读结果，还是允许跳转到独立站点
