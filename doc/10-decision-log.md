# 决策存证

| 编号 | 决策 | 理由 | 状态 |
|---|---|---|---|
| ADR-001 | 作品集与实验平台独立成两个项目 | 作品集需要稳定和安全，实验平台允许失败和资源波动 | 已确认 |
| ADR-002 | 作品集不执行任意代码 | 降低任意代码执行、资源争抢和供应链风险 | 已确认 |
| ADR-003 | 公开内容使用发布投影 | 避免草稿和半成品泄露，支持回滚 | 已确认 |
| ADR-004 | 旧项目采用人工审查后发布 | 版本、隐私、贡献和授权不能仅靠自动化判断 | 已确认 |
| ADR-005 | 首期知识网络使用关系型数据库 | 当前规模不需要图数据库，降低维护和部署复杂度 | 待工程评审 |
| ADR-006 | 详细学习记录留在 ai-dev-lab | 保持作品集聚焦，避免学习日志和公开展示混杂 | 已确认 |
| ADR-007 | 首期使用模块化单体 | 当前规模下更易测试、部署和回滚 | 待技术栈确认 |
| ADR-008 | 高保真原型确认后才开发 | 提前验证信息架构和交互，减少返工 | 已确认 |
| ADR-009 | V2 后端采用 Java 17 + Spring Boot 3 + MyBatis-Plus | 复用已有 Java 项目经验，统一认证、数据访问、测试和交付方式 | 已确认 |
| ADR-010 | 数据库采用 MySQL 8，迁移采用 Flyway | 与 Java 技术栈一致，以版本化 SQL 保证 schema 可追踪 | 已确认 |
| ADR-011 | 保留旧 Python 后端作为迁移参考，不直接删除 | 保留已验证接口和历史数据边界，降低一次性切换风险 | 已确认 |
| ADR-012 | 丢失的 V2 迁移采用复建文件 + 本地库从零重建，不使用 repair 掩盖 | 本地库无业务数据，从零重建可同时恢复迁移可复现性并完成从零建库验证 | 已确认 |
| ADR-013 | AI Translator 的对外展示名使用 LexiFlow，仓库名保持 `ai-translator` | 展示名与仓库名分离便于对外表达；对外名称必须在案例中与仓库名对应，避免审查时无法核对 | 已确认 |
| ADR-014 | 知识库 RAG 项目的对外展示名使用 Folio，仓库名保持 `ai-second-brain` | 原名偏个人效率工具语境，不适合作为产品对外表达；展示名与仓库名的对应关系显示在案例详情页 | 已确认 |
| ADR-015 | 详情页从侧边抽屉改为真实路由页面 | 抽屉不改变地址、无法分享、刷新即丢失、前进后退不可用；真实页面可直达可分享，且更符合案例档案的阅读方式 | 已确认 |
| ADR-016 | 保持暗色主题，但修正 --faint 对比度与面板层次分离 | 暗色是既定的编辑风格；实测 --faint 对比度约 3.3:1 未达 AA，且面板与背景亮度差过小导致版面发闷 | 已确认 |
