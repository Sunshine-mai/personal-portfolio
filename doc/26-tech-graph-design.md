# 首页技术网络图 · 设计稿

> 路线阶段 1 的任务 1.1。**设计确认后才写代码**（`CLAUDE.md` 交付原则第一条）。
>
> 状态：待确认 · 2026-09-13

## 1. 它要解决什么

首页目前用文字标签表达"会什么技术"，读者只能逐个读。网络图要让人**一眼看出技术的分布与关联**：
哪些成簇（同一技术栈体系）、哪些跨项目复用、哪些只出现在一个项目里。

**不是**为了炫技。判断标准：**如果换成一张表格能表达得一样清楚，就不该做成图。**

## 2. 数据模型：二部图（项目 ↔ 技术）

**两类节点**：项目（5 个）、技术（约 40 个）。
**边**：项目使用某技术。只连"项目↔技术"，**不连"技术↔技术"**。

### 为什么不用"技术共现图"（两个技术同现于一个项目就连线）

这是本设计的第一次修正，起因是先算了边的数量：

| 模型 | 节点 | 边 | 图密度 |
|---|---|---|---|
| 技术共现 | ~40 | 每个项目内部两两相连：C(10,2)=45，×5 ≈ **225** | **约 29%** → 毛线球 |
| **二部图** | 5 + ~40 | 每个项目 10 条，×5 ≈ **50** | **约 5%** → 可读 |

共现模型会**给每个项目生成一个完全图**，5 个项目叠起来就是 5 个团互相叠加，
线密到看不出任何结构——而"看不出结构"恰恰让做图失去意义。

二部图还额外满足两条更重要的要求：

1. **每条边都可直接核验**——"Folio 用了 MySQL"是可查的事实；
   而"MySQL 和 Redis 相关"是推断，容易变成夸大的暗示。
2. **跨项目复用一眼可见**——一个技术节点连着 3 个项目，就是"我在 3 个项目里用过它"。

### 数据来源：从既有事实派生，不新增一份数据

```js
// project/frontend/src/data/projects.js 里每个案例已有：
stack: [{ layer: '前端', items: ['Vue 3'], note: '…' }, …]
```

图的节点与边**全部从各案例的 `stack` 派生**。

| 好处 | 说明 |
|---|---|
| 单一状态源 | 加一个案例的技术栈，图自动更新；不存在"图里的数据和案例里的数据不一致" |
| 每根线都有出处 | 每条边都能回答"因为哪个项目" |
| 不新增审核面 | `stack` 已受 `doc/14` 台账约束（数据依赖见第 7 节） |

## 3. 布局：确定性，一次性计算

**不用实时力导向物理。**

| 方案 | 判断 |
|---|---|
| 实时力导向（d3-force 式） | ❌ **每次位置都不同 → 验收断言不了**；持续动画耗 CPU；`prefers-reduced-motion` 下要停，停了就失去意义 |
| 手写固定坐标 | ❌ 加一个技术就要重排全部坐标，维护成本高 |
| **固定种子的确定性布局** | ✅ 带种子的伪随机 + 一次性力导向迭代（约 200 次），**结果每次完全相同**：可断言、可截图比对、无持续动画 |

布局目标：**项目节点分布在外圈，技术节点被拉向使用它的项目**。
这会让同一生态的技术自然聚集（Java 系靠近使用 Java 的项目），形成可读的簇。

实现约 30 行自写迭代（斥力 + 弹簧 + 向心），种子固定，**不引入任何依赖**。

## 4. 视觉

| 项 | 决定 | 理由 |
|---|---|---|
| 渲染 | **SVG + 真实 DOM 节点**（每个节点一个 `<g>`） | 可聚焦、有 `aria-label`、可断言。**canvas 对屏幕阅读器完全不可见** |
| 项目节点 | 方形／大圆，带项目名，颜色用强调色 | 与普通技术节点区分开 |
| 技术节点 | 小圆，常显技术名（小字） | 图不能"点开才知道是什么" |
| 技术节点颜色 | 按技术层（前端／后端／数据／运行）取既有 CSS 变量 | 复用现有配色，不引入新色 |
| 边 | 细线，透明度低；高亮时提高 | 避免 50 条线抢注意力 |
| 复用提示 | 连接 ≥2 个项目的技术节点加一圈描边 | "跨项目复用"是这个图最有价值的信息 |

## 5. 交互

| 输入 | 行为 |
|---|---|
| **鼠标在图上移动** | **邻近高亮**：最近的节点及其所有连边高亮，其余变暗。这是"活的感觉"的来源 |
| 悬停／邻近某节点 | 高亮该节点 + 全部连边 + 对端节点；若邻居超过 3 个，显示"用于：LexiFlow、Folio、知衡" |
| 点击节点 | **锁定**高亮（移动鼠标不再改变）；再点一次或点空白解除 |
| **键盘 Tab** | 逐个聚焦节点（`tabindex="0"`），焦点样式用既有 `focus-visible` |
| **Enter / Space** | 等同于点击（锁定／解除） |
| 触摸 | 点击 = 点击节点 |

**为什么是"邻近高亮"而不是"节点自己会动"**：前者坐标固定、可断言；
后者位置持续变化，无法验收，且对前庭敏感用户不友好。

## 6. 可访问性与降级

| 要求 | 做法 |
|---|---|
| 屏幕阅读器 | 节点 `aria-label="Vue 3，用于 LexiFlow、Folio"`；图整体 `role="group"` + `aria-label` |
| **文字版替代** | 图下方 `<details><summary>文字版清单</summary>`，按项目列出技术。**与图信息等价** |
| 动画偏好 | `prefers-reduced-motion` 下取消所有过渡（既有规则已覆盖，需确认新元素也遵守） |
| 小屏 | 只显示连接 ≥2 个项目的技术节点，其余收进文字版 |
| 图渲染失败 | 文字版是静态渲染的，信息获取不依赖图形 |

**所以顺序应当是：先补数据（路线阶段 2 的 2.1／2.2），再实现图形。**
把它们提到阶段 1 之前，是本次设计暴露出的**真实依赖**，不是范围扩张。

## 8. 验收断言（新增到 `utils/browser-check.mjs`）

| 断言 | 期望值 |
|---|---|
| 项目节点数量 | 精确值（有 `stack` 的案例数） |
| 技术节点数量 | 精确值 |
| 边数量 | 精确值（应等于各案例技术项数之和） |
| 所有节点在可视区内 | 坐标 ≥ 0 且 ≤ viewBox 尺寸 |
| 无持续动画 | `getAnimations()` 为空；`prefers-reduced-motion` 下同样为空 |
| 邻近高亮生效 | 移动鼠标后，高亮节点+边数量 > 0 且 < 总数 |
| 高亮可清除 | 移出后高亮数量归零 |
| 键盘可达 | Tab 能聚焦节点；`:focus-visible` 生效 |
| Enter 锁定高亮 | 按键后移动鼠标，高亮不变 |
| **文字版与图等价** | 文字版技术名集合 == 图技术节点集合 |
| 屏幕阅读器标签 | 每个节点 `aria-label` 非空 |

**"文字版与图等价"是关键**：既保证图挂了不丢信息，也防止两处数据漂移。

## 9. 明确不做

- **不做实时力导向物理**：验收断言不了，且持续耗电。
- **不引入 d3 / cytoscape 等依赖**：约 30 行自写迭代足够，依赖是长期维护负债。
- **不使用第三方技术 logo 图片**：牵涉商标授权，且与既有"不使用外部图片"惯例冲突。
- **不画"技术↔技术"的边**：会退化成完全图（见第 2 节的数字），且属于推断而非事实。
- **不做"接触过但没用于项目"的技术**：无法核验，且违反"不夸大"。
- **不做更高级的知识图谱式展示**：那是独立立项的知识体系项目，本项目聚焦呈现项目与内容。
- **不做缩放／拖拽画布**：复杂度与可访问性代价高于收益；小屏用密度降级代替。

## 10. 风险

| 风险 | 应对 |
|---|---|
| 图"很酷但没信息" | 第 1 节的判断标准：若信息量不如表格，就退回表格 |
| 节点太多变成毛线球 | 二部图密度约 5%（已算）；节点总数上限 60，超了就只显示复用技术 |
| 数据过期导致图说谎 | 图完全派生自 `stack`，`stack` 受台账约束；台账过期的案例不纳入 |
| 与详情页技术栈重复 | 首页图是**跨项目总览**，详情页是**单项目分层（含调用方向）**。职责不同，不是重复 |
| 布局在窄屏挤成一团 | 窄屏改用降级视图（只显示复用技术），而不是把大图缩小 |
