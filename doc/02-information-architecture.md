# 信息架构与页面规格

## 1. 页面地图

```text
公开区
├── 首页
├── 项目列表
│   └── 项目详情
├── 知识网络
├── 学习摘要
├── 工程交付方法
├── 关于
└── 404/错误页

管理区
├── 概览
├── 项目管理
├── 知识节点与关系
├── 技术栈与决策
├── 证据与外链核验
├── 审核预览
├── 发布与回滚
└── 审计日志
```

## 2. 首页内容顺序

1. 身份、职业方向和主行动。
2. 三个代表项目与可信度摘要。
3. 能力链：需求→设计→实现→测试→部署→复盘。
4. 知识网络局部预览。
5. 精选学习轨迹。
6. 工程交付方法。
7. 联系方式和最近更新时间。

## 3. 项目列表

卡片或档案条目必须显示：项目名、问题摘要、个人角色、项目类型、技术标签、状态、最近核验时间和详情入口。筛选支持项目类型、技术方向、成熟度和年份。

## 4. 项目详情

项目首屏显示名称、结果、时间、状态、角色、技术栈、Demo、源码、运行说明和最后核验时间。正文按统一模板展示背景、贡献、架构、决策、证据、限制、复盘和关联知识。

合作项目必须额外展示“团队成果”和“个人贡献”的边界。

## 5. 知识网络

首期同时提供：

- 图谱视图：用于探索关系。
- 列表视图：用于搜索、移动端和无障碍访问。
- 节点详情：定义、关联项目、决策、证据、学习状态和详细记录链接。

图谱不是唯一入口，也不作为装饰背景。

## 6. 设计约束

- 视觉方向：编辑式工程档案馆。
- 避免紫色渐变、霓虹光晕、卡片堆砌和虚假科技感。
- 设计必须使用真实项目内容，不使用 Lorem Ipsum。
- 原型必须覆盖默认、加载、空、错误、成功、禁用和焦点状态。
