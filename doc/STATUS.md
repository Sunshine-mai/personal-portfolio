### 本轮改动（首页首屏与互动层）

起因是两条反馈：「首屏不铺满、下一节的编号漏进第一屏」与「整页太沉闷」。

- **首屏**：`min-height` 原来固定 680px，与视口无关。实测 1440×900 下导航 73 + 首屏 680 = 753，
  只填满导航以下的 **82%**，而下一节编号落在 **884px**——正好在第一屏最底边露出一行。
  改为跟视口走（`100svh`）后两个问题同时消失。H1 从 88px／3 行／269px 收到 62px／2 行。
- **右列**：4 条静态事实（在 405px 里靠 `space-between` 拉到两端，中间是空的）→
  5 个真实项目索引。悬停/聚焦展开该项目**真实的技术分层首项**，点击定位到下方对应卡片。
- **互动层**：一律用**位移**而不是亮度。光斑峰值一度给到 `.17`，被判为"抢主角风头"；
  但"太亮"和"太死"是两个方向的问题——亮度是有预算的（标题必须最亮），位移没有。
  现在光斑中心上移 72px、峰值 ≤`.04`，配合反向视差与卡片／技术栈／目录树／翻页悬停。
- **编号**：`01 / 5 PROJECTS` 这种长串要 148px 才放得下，会把标题挤开、窄屏还会折行。
  收成光秃秃的 `01`，36px 窄栏紧贴标题；二级页面与收尾区块同一规则。
- **字体**：`Noto Serif SC` 此前只写在 `--serif` 里却**从未加载**——本机装了它的机器看着正常，
  访客机器会落到系统衬线体，**两边字形不一致**。已补进 Google Fonts 导入。
  同时去掉中文的假斜体（`<em>` 自带浏览器默认斜体，只删 CSS 规则是不够的）。
- **锚点**：改用 `offsetTop` 计算。`v-reveal` 的元素入场前带 `translateY(26px)`，
  而 `getBoundingClientRect` 会把它算进去——首屏卡片被点击时稳定偏低 28px（实测 96 → 68）。

> 两个教训都关于**断言测错了对象**：光斑偏移 430px 时，"transform 变了"的断言照样通过；
> 假斜体在"只删了 CSS 规则"之后依然存在。断言必须量最终形态，不是"有没有这段代码"。
