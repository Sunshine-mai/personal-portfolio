# 系统架构设计

## 1. 架构目标

- 公开展示稳定可用。
- 管理端可维护但不影响已发布版本。
- 内容可追溯、可审核、可回滚。
- 不执行任意代码。
- 未来实验平台完全独立。

## 2. 推荐架构

```text
访客浏览器
    ↓
Nginx / HTTPS
    ├── 前端静态资源或前端服务
    └── 公开只读 API
             ↓
       作品集后端
       ├── 公开内容查询
       ├── 管理认证
       ├── 内容修订
       ├── 审核发布
       ├── 知识网络
       └── 证据与外链状态
             ↓
       关系型数据库
```

## 3. 公开与编辑隔离

```text
编辑数据
  → 校验/脱敏/审核
  → 发布快照
  → PublishedProjection
  → 公开 API
```

公开查询不能直接读取草稿表或管理员编辑状态。

## 4. 运行隔离

```text
personal-portfolio
  只展示审核通过的成果，不执行代码

未来 dev-playground
  独立项目，负责实验、Skill 测试和未完成项目运行
```

两者不共享数据库、进程、Docker 网络或发布流水线。实验平台成熟后的内容必须经过人工审查和发布快照流程才能进入作品集。

## 5. 初期架构原则

- 优先模块化单体，不提前拆微服务。
- 知识网络首期使用关系型数据库节点与边，不引入图数据库。
- 公开站点不依赖实时外部 API 才能渲染正文。
- 外链核验是后台任务或手动工具，不阻塞访客页面。
- 发布失败时继续服务上一稳定版本。
