# V5 正式前端迁移记录

## 项目详情由抽屉改为真实路由页面（2026-09-12）

### 变更原因

详情原先以侧边抽屉呈现，页面地址不变、无法分享、刷新即丢失、浏览器前进后退不可用。
改为真实路由页面后，每个案例都有独立 URL，可直达、可分享、可刷新。

### 结构调整

```text
src/
├── App.vue              外壳：导航 + 路由出口 + 页脚 + 全局提示
├── main.js              挂载路由
├── router/index.js      / 与 /projects/:slug，含锚点与滚动行为
├── composables/useToast.js
├── data/projects.js     案例数据、归一化、列表与详情数据源（两页共用）
└── views/
    ├── HomeView.vue     首页：首屏、代表项目、视觉与剪辑、工程方法、关于我
    └── ProjectView.vue  详情页：过程证据图组、问题与边界、下一步、上下篇导航
```

### 行为变化

- 项目卡片由按钮改为链接，整张卡片可点击，指向 `/projects/<slug>`。
- 详情页支持深链直达；未知 slug 显示 404 状态并提供返回入口。
- 详情页底部提供上一个／下一个项目导航。
- 图组的键盘左右切换保留；不再需要 Escape 关闭。
- 首页筛选无匹配项时显示空状态，不为填满版面而放内容。

### AI Second Brain 演示账号与采集边界（2026-09-12）

采集前发现该项目数据库内混有作者本人的真实资料，因此先建立独立演示数据集，再采集截图。

演示数据集（只新增，未修改或删除任何现有数据）：

- 通过公开注册接口新建演示账号 `demo_showcase`（普通用户角色）。
- 上传两份自撰演示文档（`RAG Workflow Notes`、`Knowledge Base Guidelines`），
  均标记为私有；经解析、递归切片（500/50）与本地 BGE 向量化，产生 3 + 2 共 5 个片段。
  向量化在本机完成，不产生外部调用费用。

采集过程中的两项发现与处置：

1. **跨账号检索会带上被标记为公共的文档。** 检索条件是 `s.user_id = ? OR d.is_public = 1`，
   而数据库中有 3 篇文档 `is_public = 1`。因此演示账号提问时，返回的引用里混入了
   作者本人的项目说明文档正文。采集脚本在写入截图前设置了**内容级**校验
   （检测只出现在他人文档中的特征短语），该张截图未被采用。
   经项目所有者确认，「设为公共」是设计意图，因此不修改该标记；
   采集时采用临时置私有、采集后立即还原的方式，全程只改动 `is_public` 一个字段的 3 行，
   并在结束后校验还原结果与原值一致。附带观察：公共文档参与跨账号检索会挤占召回名额，
   使演示账号的回答质量下降，这是该设计的一个真实代价。
2. **新建会话发送首条消息时前端会崩溃。** `useChat.js:85` 记录 AI 占位消息下标，
   `useChat.js:98-101` 在后端自动创建会话时更新 `currentSessionId` 并刷新会话列表，
   触发 `watch` 调用 `loadMessages`，而 `loadMessages:51` 会**整体替换** `messages` 数组，
   把尚未填充完的 AI 占位消息一起冲掉；第 105 行再按旧下标追加内容时读到 `undefined`，
   界面显示 `Cannot read properties of undefined (reading 'content')`。
   触发条件为全新会话的首条消息；已有会话内追问不受影响。
   经同步接口 `/chat/send` 与流式接口 `/chat/stream` 直接验证，后端两个接口本身均正常。

   修复（已提交到该项目）：

   - 新增 `streamingSessionId`，记录本轮流式请求期间由后端自动创建的会话 ID。
   - `watch` 在该 ID 上跳过重载，避免覆盖正在接收的 AI 消息。
   - `onMetadata`、`onDelta`、`onError` 改为先取值判空再写入，不再裸下标访问。
   - `onDone` / `onError` 结束时清除该标记，保证后续正常切换会话不受影响。

   修复后复跑采集，对话正常流式渲染，引用面板可展开，未再出现该错误。

最终新增文档管理页与检索对话两张截图，对话页展示的是材料不足时明确说明缺失、
而不是编造补全的行为；三条引用片段全部来自演示账号自有的演示文档。

### LexiFlow 边界证据采集过程（2026-09-10）

LexiFlow 的后两张截图由浏览器脚本驱动本地实跑采集，不是设计稿：

1. 启动后端（venv 解释器，端口 8000）与前端（Vite，端口 5173）。
2. 无头 Chrome 打开 `/translate`，填入英文句子并点击「翻译」，等待模型返回。
3. 同一浏览器会话内连续翻译，观察游客配额递减直到被拦截。
4. 截图被拦截后的页面状态。

实测结果：

```text
第 1 次  每天一小步，胜过一大步。        页面提示：游客今日可免费翻译 2 次
第 2 次  好工具融入工作之中。            页面提示：游客今日可免费翻译 1 次
第 3 次  交付真实存在的最小事物。        页面提示：游客今日可免费翻译 0 次
第 4 次  被拦截，前端跳转到登录页
```

结论：游客配额按匿名标识独立计数，耗尽后引导登录而不是静默失败。同一句子在不同次请求下译文会略有差异（模型输出非确定性），因此案例描述不声称译文可复现。

补充说明：首次采集时曾错误地认为配额未生效，实际原因是采集脚本用于提取页面文案的正则未匹配到嵌套元素，属于脚本缺陷而非产品缺陷。
