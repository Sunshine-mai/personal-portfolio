# V5 正式前端迁移记录

## 范围

将 `prototype/portfolio-v5.html` 的信息架构和视觉方向迁移到 `project/frontend/` 的 Vue 3 + Vite 应用。正式页面继续只读取 `/api/public/projects` 的已发布内容，后端不可用时使用安全静态回退数据。

## 已实现

- 深色作品集视觉、字体层级、项目列表和响应式布局。
- 代表项目筛选：全部、独立开发、原型方案、合作项目。
- 项目详情抽屉，支持读取 `/api/public/projects/{slug}`。
- 工程方法、视觉与剪辑待补状态、关于我和复制邮箱反馈。
- 保留 Vite 代理：前端 `1001`，后端 `2001`。

## 验收边界

- 当前项目图片沿用 V5 原型路径 `/prototype/assets/v5/`；正式部署前应将已授权截图迁移到前端 `public/assets/`，避免部署时依赖原型目录。
- 后端项目字段以现有 Java `Project` 实体为准；标签和图片属于前端展示增强字段，未写入后端数据库。
- 正式测试应覆盖 API 成功、API 失败回退、筛选、详情抽屉、Escape 关闭和移动端导航。

已验证：

- 首屏、代表项目、视觉与剪辑、工程方法、关于我、页脚六个区块全部正常渲染，无破图、无错位。
- 4 张项目卡片全部渲染，封面来自 `public/assets/v5/` 的真实截图。
- 后端不可用时不白屏，状态行显示“后端不可用 · 当前显示安全静态回退数据”。
- 后端已连接但无已发布内容时，状态行显示“后端已连接但暂无已发布内容 · 当前显示安全静态回退数据”，不再误报为“内容来自公开 API”。

本轮修复的问题：

- 首屏统计曾把 4 个项目全部计为独立项目，与 `doc/19` 的“2 独立 / 1 原型 / 1 合作”不符。原因是分类取自展示文案字段而非 `project_type` 机器值，
  导致“原型方案”和“合作项目”筛选恒为空。修复后首屏显示“2 个独立项目”。
- 同一原因会使 `prototype` 与 `collab` 筛选失效，修复后可正确过滤。
- API 返回标签时曾被子级回退标签覆盖，已改为优先使用 API 标签。

尚未覆盖：详情抽屉打开与 Escape 关闭、筛选按钮点击、移动端菜单展开、键盘操作。这些需要可交互的浏览器会话，仍属于待补证据。
