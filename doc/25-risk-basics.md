# 风险常识（本仓库）

> 这份文件回答一个问题：**这个操作不可逆吗？坏起来会坏成什么样？**
> 面向任何执行者——人，或者 AI。它不要求你懂实现细节，只要求你在放行前说清三件事。
>
> 对应的强制要求写在 `CLAUDE.md` 的「不可逆操作」一节；本文件是逐项说明。
> 最后更新：2026-09-13

## 为什么值得单独写一份

AI 出错时**不会说"我可能错了"**。它会用流畅、笃定、专业的语气，把一件事说得像标准流程。
所以判断的依据不能是"它讲得有没有道理"，只能是事实。

本项目已经有实际证据：

| 事件 | 实际发生的事 |
|---|---|
| 密钥进过要公开的仓库 | Folio 的 `application-dev.yml` 里有真实数据库密码。发现得早，才只限于 amend 重写；晚一步就永久留在历史里 |
| 一次错误归因 | 执行者用笃定的语气断言门禁失败是「`-DargLine` 被 cmd 破坏引号」，还配了完整推理——**实测完全不成立**，真实原因是 PATH 里有畸形条目让 `cmd.exe` 搜不到 `mvn` |
| 一次误删 | `git reset --hard` 把同在工作区、尚未提交的修复一并抹掉，导致后续基于旧代码得出错误结论 |

## 放行前只说三件事

| # | 要问的 | 不要看的 |
|---|---|---|
| 1 | 它要碰哪里、做什么动作 | 不要看语气、不要看它多自信 |
| 2 | 我信不信它做**接下来的**事（不只是这一条） | 不要因为这一条"很合理"就放行 |
| 3 | 出事我担不担得起 | 不要看"概率很小" |

**第 2 条最容易被忽略。** 放宽执行权限时，覆盖范围是**同类后续操作**，不是眼前这一条命令。

## 本仓库的不可逆操作清单

| 操作 | 能否回退 | 坏起来会怎样 | 放行前该确认 |
|---|---|---|---|
| `git push` 到公开仓库 | ❌ | 一旦公开，历史里删不掉；密钥只能靠**轮换**补救，不是删除 | 目标仓库是公开还是私有；本次提交是否已过秘密扫描 |
| `git push --force` / `--force-with-lease` | ❌ | 覆盖远端历史，协作者的工作会丢 | 是否真的只有自己用这个仓库；改动窗口是否还开着 |
| 发布到线上（Netlify） | ✅ 可回滚到上一版 | 访客**立刻**看到坏页面 | 门禁是否全过；深链是否返回 200 |
| 删除远端仓库里的文件 | ❌ | 从历史里拿不回来 | 本地是否还有副本；是否已加进 `.gitignore` 防止再被带上 |
| 改动或轮换凭据 | ❌ | 正在运行的系统会连不上 | 有几处在用这个凭据；改完谁需要同步 |
| `git reset --hard` | ❌（未提交部分） | 工作区里未提交的修改直接消失 | 工作区有没有要保留的改动 |
| 修改**其他项目**里的文件 | 视那个仓库 | 影响到另一个项目，且可能超出本项目范围 | 授权边界；是否属于本项目该做的事 |
| 放宽执行权限（提权） | ✅ 下次操作恢复 | 覆盖范围是**同类后续操作**，期间不再逐次询问 | 它能否说出**具体的技术必要性**，而不是"这样方便" |

## 关于"放宽执行权限"

本项目的正常开发流程就会撞到三类环境边界，**它们都不是危险操作**：

| 边界 | 表现 | 为什么正常流程会撞 |
|---|---|---|
| 写路径 | 只能写工作区内，其余报 `file access denied` | 需要改另一个仓库的配置 |
| 子进程与管道 | 禁止以管道捕获子进程输出：`spawn EPERM`、`couldn't create signal pipe` | 构建、跑测试、浏览器验收、git 都要起子进程 |
| 网络 | git 联网操作失败 | 拉取、推送 |

所以**申请放宽本身是合理的**——受限模式下它确实干不了这活。但要注意两点：

1. 它**一次只对一次操作有效**，所以会连续弹窗；
2. 正因为连续弹窗很烦，才容易出现"干脆一次全放开"。

**此时要判断的不是"这一串命令危险吗"，而是"放开之后它做的每一件事，我信不信"。**
单个看都无比正常（构建、测试、验收、推送），合起来就是一次全放开——**"看起来合理"恰恰是这类请求最危险的地方**。

## 声明格式（执行者必须给出）

```text
【不可逆操作】
做什么：
不可逆在哪：
能否回退：
影响范围：
```

填写要求：

- **「能否回退」写不出具体方式时，直接写「无法回退」。** 含糊比写"无法回退"更危险。
- 「影响范围」要写清是本地、自己的远端，还是公开可见。
- 放宽权限的声明里必须写明**它覆盖的是后续同类操作**，而不是这一条。
- 声明之后要**停下来等确认**，不能边说边做。

### 一个填好的例子

```text
【不可逆操作】
做什么：把 folio.git 的首次提交推送到公开仓库
不可逆在哪：公开后内容进第三方托管，本项目无法单方面撤回
能否回退：无法回退（唯一可挽回窗口是"尚未推送给任何人"的阶段）
影响范围：公开可见；影响 ai-second-brain 一个仓库，不涉及其他项目
```

## 说不清的时候怎么办

**不批准。** 拒绝的代价永远小于点错的代价。

然后把它变成可回退的形式再试，例如：

| 原本想做 | 可回退的替代 |
|---|---|
| 直接推到公开仓库 | 先推到本地分支或私有仓库，确认无误再合并 |
| 直接改远端历史 | 先在本地重写并验证，把强推留到最后一步 |
| 在真实数据上试迁移 | 先在空库上从零跑一遍 |
| 直接改线上内容 | 先在本地预览，看过了再发布 |

## 为什么这套东西放在仓库里

放在对话里，下次就没了；写进 `CLAUDE.md` 与本文件，任何接手的人——包括未来的 AI 会话——都会读到。

**能机制化的判断，就不要指望某个人记得。** 本项目已经有几件不再依赖记忆的事：

| 需要判断的事 | 已机制化的方式 |
|---|---|
| 密钥不能进仓库 | pre-push 钩子 + `utils/verify.mjs` 秘密扫描 |
| 改动不能破坏页面 | 47 项浏览器验收，退出码即门禁 |
| 后端测试参数不能丢 | 写进 `backend/pom.xml`，不再靠文档记忆 |
| 不可逆操作要先说明 | 本文件 + `CLAUDE.md`（**靠遵守，尚未自动强制**） |

最后一行是诚实的：这一条目前还没有机器强制，它靠执行者照做。**把它写下来，是让它有可能被遵守的第一步。**
