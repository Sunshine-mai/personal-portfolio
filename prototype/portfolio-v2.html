Delivery system

把一次项目经验，变成下一次交付的起点。

从需求边界到发布证据，过程有固定结构，但技术方案始终服从真实问题。

01 / FRAME

定义边界

明确用户、目标、角色和不做什么，避免先堆功能。

02 / DECIDE

记录取舍

写下候选方案、选择理由与代价，保留可解释性。

03 / BUILD

小步实现

每段功能独立运行，前后端、数据和权限协同推进。

04 / VERIFY

多层验证

单元、接口、数据库、构建和浏览器路径共同证明结果。

05 / COMPOUND

归档复用

形成审查包、案例档案与通用规则，供下一个项目直接复用。

Evidence ledger

先给结论，再让证据说话。

作品集不把“做过”当作最终证明。每项公开声明都有对应的来源、核验等级和发布边界。

Public release gate

真实可展示，
不等于全部都要公开。

项目资料先完成版本、授权、密钥和事实审查，再生成公开档案；公开站点只读取经过审核的快照。

  • 独立项目：功能、决策、测试与交付证据
  • 合作项目：团队成果与个人贡献明确分栏
  • 原型项目：清楚展示边界与下一步验证计划
